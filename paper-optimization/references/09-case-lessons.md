# 去标识化案例教训

本页只保留跨项目可复用的失败模式，不保存客户、雇主、平台、论文题目、项目代号、真实路径、账号、预算或运行标识。

## 弱信号不是成功

一个候选在单次运行中高于 baseline，并不证明方法稳定。至少核查：

- baseline 与候选是否来自同一冻结协议；
- seed 是独立训练 seed，还是同一训练结果的重复评测；
- 改善是否大于 baseline 波动和预声明的有效阈值；
- 不利的补充实验是否被完整保留；
- 最终方法是否经过 checkpoint 重载和干净重跑。

小样本梯度方向、局部大梯度或单次显著提升都只能形成机制假设。若多 seed 均值未过预声明门槛，应报告负结果，而不是选择最好 seed。

## Trial 血缘不能拼接

一个正式结果只能引用一个真实 trial 的执行、源码、配置、receipt、artifact 和 method hash。相同分数不能把多轮运行拼成 canonical result。修复血缘需要重新运行或降级结论，增加 API 或 GPU 消费不会自动修复证据链。

## 链路成功不等于方法成功

训练、评测、重载和打包全部退出 0，只证明执行链可重放。候选低于 baseline 时，状态仍是“工程链路通过、研究目标失败”。反过来，本地有正收益也不能替代目标平台、容器或隐藏评测的实际验收。

## 先跑最便宜的判别实验

长轨迹前先用便宜 pilot 检查效应量、噪声、身份链和部署闭环。只有短跑通过预先定义的晋级条件，才扩大 seed、步数或模型规模。预算、硬件、时长和阈值全部从当前任务读取，不从案例继承。

## 交接时保留失败

失败实验保留原始配置、日志和原因；不要就地覆盖。交接稿区分：

- 已观察事实；
- 有证据支持的解释；
- 尚未验证的假设；
- 下一次有限、可证伪的实验；
- 明确停止条件。
