# 故障分型与避免无效投入

| 现象 | 先检查 | 最小处理 | 保留什么 |
|---|---|---|---|
| 飞书已登录但 CLI 拒绝 | 文档资源授权与身份、错误码 | 已授权读取渠道或可访问副本；标记缺失 | URL、revision、错误，不保存认证信息 |
| SSH 等待后关闭 | 实例状态、连接信息、会话超时 | 有限重连；确认后建立专用 key | 错误与恢复方式 |
| Control socket 太长／不见了 | 路径长度、master 是否存活 | 私有短目录／新连接 | 失败命令与新的受控入口 |
| 非交互找不到 Python | PATH、conda激活与真实解释器 | 固定绝对解释器 | 环境版本 |
| 导入脚本参数不匹配 | 远端是否仍旧版本、函数签名 | 核对哈希再部署版本 | 前后源码与原失败 |
| GPU可见但训练CUDA失败 | 实际设备节点、runtime架构、proc/socket权限 | 最小必需兼容修复并重跑负测 | stderr、必要strace、权限证明 |
| 顶层CUDA能用、fork失败 | `/proc/self`规则绑定与子PID | 可信controller分别顶层训练/评分 | 两条路径的正负对照 |
| pytest突然几十个收集错误 | 是否扫描work/旧checkout/备份目录 | 按仓库指定测试目录运行 | 原命令；别把测试收集错当算法错 |
| 短超时测试偶发-9 | 启动准备耗时与被测期限混在一起 | 分开准备和目标行为，保留真实清理断言 | 故障复现与回归 |
| API聊天能用、工具不通 | harness实际接口、模型/tool schema、认证继承 | 同正式链路的短工具闭环 | 原始请求/返回与退出码 |
| 原始流出现多个thread | 主/子thread关联和完成归属 | 严格匹配身份；拒绝非授权工具 | 全流及按轮快照 |
| Agent说完成但没有checkpoint | 实际文件、训练命令、重载评分 | 判未完成；查对应阶段 | 不改写自述来遮盖缺证据 |
| RPC几分钟没增长 | GPU train step是否在增长、同步工具是否待返回 | 健康则继续等 | 采样时刻、PID、step |
| 梯度非零但准确率没动 | NLL/margin/翻转、评测粒度 | 诊断学习量，不急着换公式 | 逐样本预测、有效epoch |
| 候选平均更差 | 同协议与全部seed、训练动态 | 标负结果；用可证伪机制决定下一轮 | 失败方法快照和完整结果 |
| observer报告很大 | 模型是否收到大量无关采样 | 模型返回紧凑摘要，原始证据全存档 | 完整artifact与摘要关联 |
| 跑满墙钟但有效时长不足 | 阶段分类、缺失事件、排队、重复时间 | 继续真实迭代或标未达标 | 原始时间窗，不补造事件 |
| 同一 seed 跑三次却要求跨 seed 稳定 | training_seed 与 replicate_id 是否混用 | 补跑预声明的不同 seed，或诚实降级为同 seed 重复 | 每轮 seed、run/trial ID 与配对表 |
| 数值提升达标但 QA 仍判失败 | 题面阈值、结果身份链、正式汇总和平台入口 | 逐门修协议与证据；不要先加 API/GPU 预算 | 原始回执、源码/产物哈希、部署日志 |
| Baseline result 拼入多轮字段 | execution/source/artifact/receipt 是否属于同一 trial | 每个正式结果只绑定一轮，重复实验另列 paired_runs | 一对一身份索引与 checksum |
| 连续评分公式已有但有效改善阈值缺失 | “怎么算分”与“何时算有效”是否混为一谈 | 在题面冻结阈值、波动规则和 seed 方案后再长跑 | 版本化 instruction 与协议哈希 |
| GPU/API 花费增长但不可交付项没减少 | 消费是否对应当前失败门槛 | 暂停新消费，先修无需 GPU 的契约、封装或部署问题 | 成本台账与门槛差项映射 |

## 优化工作里的“停下来”不是同一件事

1. **停止某候选**：结果不支持它，但保留数据；可以继续其他有依据的方法。
2. **暂停新消费**：没有可执行下一步、认证连续失败、预算临界；先保存现场。
3. **停止长跑**：达到真实终止条件，或安全／成本边界触发；记录已完成的有效时长。
4. **题目 NOT READY**：部分最终门槛没通过，并不否定已完成的开发工作。

避免两种浪费：把最终收益门槛设成永远无法开始探索的理由；或明明链路失败却连续开十小时作业。合理顺序是先一轮真实闭环，再持续方法迭代。

## 每次修复必须回答

这是观察到的问题还是猜想？改动针对哪个原因？什么验证能证明修复？有没有削弱公平性、隔离或评分？如何回滚？费用上限是什么？

别将所有项目都升级成自建沙箱和调度平台。若平台已提供可靠执行器，接入它更合适；自建 Linux 隔离边界是特定环境限制下的工程成本，不是默认要求。
