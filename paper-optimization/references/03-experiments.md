# 实验协议、真实验证与统计

## 1. 先保存不可混淆的版本

每个 run 有独立 ID 和新目录，记录 source commit + dirty diff／源码哈希、候选文件哈希、配置、模型 revision、数据清单和顺序、seed、环境、命令、开始／结束、退出码。代码在运行时继续编辑也不能改变已启动实验的快照。

协议至少冻结：模型、数据切分与预处理、主指标方向、训练参数量、batch／accumulation／step、优化器、学习率及日程、dtype、裁剪、校准样本、checkpoint 选择、seed 与评测预算。并非每题都需要相同字段，但不能缺少影响公平性的字段。

实际训练量：

`样本呈现数 ≈ optimizer_steps × micro_batch × accumulation × world_size`。

再除训练样本数得近似 epoch。最后不完整 batch、动态打包、变长序列需用真实 sample-order／token 记录修正；固定 step 不一定固定有效 token 数。

## 2. 四级验证，而不是测试数量竞赛

| 级别 | 真实动作 | 可以说明 | 不能说明 |
|---|---|---|---|
| 张量／CPU | 形状、dtype、有限性、初始化函数一致、梯度路径 | 接口与局部逻辑成立 | GPU 可用、准确率提高 |
| GPU 冒烟 | 实际底座、真实样本、前后向、保存、独立重载 | 训练与评分链路通 | 充分训练或稳定收益 |
| 开发比较 | 预先固定协议下成对 seed、完整训练 | 此开发协议下差异 | 未见任务／大模型一定提升 |
| 最终确认 | 冻结方法、未用于选择的数据／seed、干净重跑 | 限定范围内可复核结论 | 超出范围的普遍结论 |

如果方法依赖 GPU 专有路径、量化内核或分布式通信，必须在实际目标硬件验证。不要为了凑“零 skip”用静态断言代替 Linux 权限测试。

## 3. baseline 必须有可辨识的含义

分别命名 `unadapted`、`naive_adapter`、`author_reference`、`candidate_X`，保存每一个的协议。它们偶然同分，也不能合并概念。朴素基线不是故意损坏的实现；正确修复低精度问题后候选增益变小，应接受事实。

baseline 和候选共用 seed、样本顺序、训练步数、评测顺序及可用校准信息。若候选额外使用梯度标定，记录开销；若任务限定总计算预算，需要把该开销计入，而不是只比较可训练参数。

## 4. checkpoint 验收

1. 训练保存实际可加载参数，不只保存一个分数字符串。
2. 保存模型／tokenizer revision、适配器位置、rank、scale、dtype 及候选哈希。
3. 恢复训练若属于要求，还要保存 optimizer、scheduler、随机状态和数据位置。
4. 新进程按固定底座和协议加载 checkpoint 重新前向，比较保存预测或指标。
5. 容差必须解释来源；不可为让结果通过随意扩大。`--compare-saved` 也需核对它究竟比较了什么。
6. 冻结底座、参数预算和允许修改文件再次校验。

CPU 恢复等价测试、GPU BF16 重载测试和目标平台 verifier 各有不同作用。

## 5. 统计口径

对相同 seed 记录 `B_i`、`R_i`、配对差 `D_i=R_i−B_i`。低值更优的指标反转差值方向后再解释，原始值仍保留。

- 报告所有预声明 seed、均值、样本标准差（ddof=1）、配对差与失败项。
- 分别区分跨 seed 波动、评测样本不确定性、数据分布迁移。
- 三个 seed 是低成本开发起点，不是统计充分性的通用定理；样本方差为零不代表总体没有方差。
- 开发集反复选方法后的最优分数存在选择偏差。最终确认时冻结候选和选择规则。
- 某 seed 超时／OOM 不能静默丢掉再取剩余均值；结果标为不完整并解释。
- 离散准确率的最小粒度由评测样本数决定；一两个样本翻转不能自动推导稳定性。

有需要时用与数据结构一致的 bootstrap／配对检验或分组统计，但不要凭极少 seed 给出强置信结论。样本级 bootstrap 与 seed 级方差回答的是不同问题。

## 6. 归一化评分只在规则需要时使用

若高值更优且规则定义 `S=(R−B)/(U−B)`，必须确保 U>B，B 有实测依据，U 有事先固定的合理依据，并绑定同一协议。准确率可用理论上界 1，但它不是唯一平台规则；低值更优指标不能直接套此式。

不得看到结果以后再降低 U 或有效改善阈值来让候选过线。方差倍数门槛和归一化区间都必须来自当前协议，并非通用显著性定义。专家注解中应写清 U 的论据和来源；没有锚点仍可做 raw score 探索，但不能生成声称正式有效的 reward。

## 7. 负收益诊断顺序

先验数据／标签／mask／分词／评分，再验底座冻结、参数进 optimizer、梯度与实际更新，再看预算是否足够，最后检验机制。建议记录：

- train loss 首尾窗口及有效 token 数；
- dev NLL、margin、预测翻转及错误类型；
- 裁剪前后梯度、A/B/scale 范数、相对权重更新；
- 逐层输出扰动、非有限值、有效秩与奇异谱（与假设相关时）；
- 标定、训练、评测、同步和数据加载分项时间。

“scale 太大”“8 个标定样本过拟合”只能先标为解释候选；需要相应消融或诊断支持。不要只依据 loss 和准确率背离就断言唯一原因。

## 8. 辅助汇总脚本

输入的每一行必须是同一协议、同一 seed 的真实成对结果：

```json
{
  "protocol_id": "frozen-v1",
  "expected_seeds": [17, 29, 43],
  "pairs": [
    {"seed": 17, "baseline": 0.6875, "candidate": 0.7109375, "status": "ok"},
    {"seed": 29, "baseline": 0.703125, "candidate": 0.6953125, "status": "ok"},
    {"seed": 43, "baseline": 0.6953125, "candidate": 0.703125, "status": "ok"}
  ]
}
```

```bash
python3 /path/to/paper-optimization/scripts/paired_summary.py \
  --input pairs.json --metric-direction higher \
  --upper-bound 1 --min-normalized-gain 0.15 --sigma-multiple 3 \
  --output summary.json
```

这三个阈值选项是显式选择，不会默认应用于别的论文。脚本保存输入哈希；遇到缺 seed、重复、失败或非有限值会拒绝，不能证明输入本身来自真实训练。只有 source artifacts 能证明这一点。
