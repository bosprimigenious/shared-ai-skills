# 论文拆解、相关方法与候选设计

## 1. 不按章节顺序读完才动手

第一遍抓问题、方法、主要实验、局限；第二遍沿当前优化面读公式、附录和代码。产出以下对应关系：

`论文主张 → 公式／算法步骤 → 作者代码 → 当前实现 → 能观察的量 → 可修改点`。

对每项记录张量形状、数据来源、随机性、精度、训练／推理开销。特别检查正文、表格、默认参数和脚本是否互相矛盾。保留两个说法的来源，并用明确选定的实现版本作为实验依据。

不要因为代码变量 A/B 名字与论文相反就认定 bug，先对照矩阵乘法与维度。

## 2. 先提出可证伪的瓶颈

| 观察 | 可以提出的假设 | 优先看什么 | 不应直接下的结论 |
|---|---|---|---|
| loss 几乎不变 | 参数没训练、信号太弱、数据太少 | requires_grad、梯度、optimizer 参数组、样本呈现数 | 换一个初始化一定好 |
| loss 降，准确率不变 | 离散指标分辨率低或任务不一致 | NLL、margin、逐样本预测翻转 | 完全没学习 |
| train 改善，dev 下降 | 过拟合、分布偏差、噪声校准 | train/dev gap、错误类别、样本去重 | 仅凭一条曲线认定过拟合 |
| NaN／爆梯度 | 尺度、精度、mask 或优化器问题 | 第一处非有限张量、裁剪前梯度、step 更新比 | 只把学习率减半结束排查 |
| 性能慢、GPU 利用率低 | CPU／数据／同步／小算子瓶颈 | profiler、tokens/s、端到端阶段耗时 | 立刻换最贵 GPU |
| rank 增大收益饱和 | 缩放退化、方向冗余、数据不足 | 实际更新谱、有效秩、层间预算 | 数学满秩等于更强泛化 |

小规模诊断的目标是排除错误解释。先记录预测，再运行；结果相反就修正假设，不回头编理由。

## 3. 相关工作怎么检索

来源顺序：原论文和作者仓库 → 直接前后续论文 → 同一机制的相邻问题 → 维护者官方实现。搜索不是收集标题，至少读清适用条件、额外成本和失败边界。

建议检索组合：`paper title official implementation`、`核心算子 initialization gradient scaling`、`method name ablation limitations`、`目标瓶颈 optimizer quantization`。核对作者身份、论文版本、代码 commit、许可证与维护日期。不要把第三方博客的性能数字写成已在本项目复现。

每篇相关工作只摘四点：解决的失败模式、关键数学或工程变更、当前接口能否表达、最低成本对照实验。新方法若需要换优化器／rank／数据，就明确属于另一个优化面。

## 4. 方法阅读与局部推导

先从当前论文、作者仓库和直接前后续工作建立阅读清单，不在公共 skill 中固化某个用户项目的方法或访问日期。每项至少回答：

- 当前实现是否忠实于论文公式、张量形状和初始化；
- 候选机制依赖哪些额外数据、参数、前后向或优化器状态；
- 迁移后仍然比较了同一个优化面和资源预算吗；
- 小模型、短步数或代理数据上的结果能支持到什么范围；
- 同名方法是否来自同一作者和同一公式。

局部推导必须从当前实现重新做。写出有效参数关于可训练参数的链式法则，检查零初始化是否切断一阶学习信号，并区分“首步梯度更大”“更新方向更合理”和“最终泛化更好”。这些不是同一主张，分别需要诊断量、消融和确认实验。

只有初始化接口时，可考虑方向选择、正交化、输入统计校准、权重／梯度感知、逐层或逐通道尺度，以及保持初始函数不变的参数化。需要改 forward 或优化器的方案，先检查是否越过当前任务的可修改边界。

## 6. 从想法变成可实现实验

一张候选卡包含：

- 问题证据：哪个可测现象支持它。
- 机制：一句因果解释和必要公式。
- 改动：确切模块、张量、额外状态与返回接口。
- 不变量：初始函数、底座冻结、参数量、预算、可用数据。
- 预测：应观察到的梯度／更新／时间变化。
- 失败条件：什么结果会否定当前解释。
- 成本：标定样本数、分解复杂度、内存、额外前后向、训练时间。
- 最小对照：baseline、候选、必要的单因素消融。

优先级默认按“能否公平验证 → 机制证据 → 成本和风险 → 可能收益”排序。若同一开发集试过很多方法，先计划确认集，再增加第十个公式。

## 7. 面向其他论文的迁移

- 推理加速：先 profile，固定质量／输出语义，再比较延迟分位数、吞吐和端到端时间；区分预填充、解码、编译、缓存冷启动。
- 量化／压缩：固定校准数据与位宽／压缩预算，验证重建误差、任务质量、实际部署内存及算子支持；保存 scale/zero point 等状态。
- 视觉／生成：固定预处理、采样、分辨率和评测实现；随机生成用同一评测预算，不能只挑最好图。
- 检索／排序：检查训练和索引泄漏、分组划分、负采样、公平候选池与索引构建成本。
- 非训练算法：可以用性质测试／精确解／小规模枚举验证，再做性能测量；不要硬套训练 loss、checkpoint 或 10h 门槛。

共同问题始终是：改进来自哪个机制，证据能否排除更简单的解释？
