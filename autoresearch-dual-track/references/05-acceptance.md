# 聚合验收门禁

## 资源与恢复

- 成本台账完整，小时/包日选择有当前价格依据；
- 正式窗口包含合理补测余量；
- 租赁磁盘不是唯一副本；
- 换容器/换机恢复演练通过。

## 双轨

- 两条轨迹的模型/provider、起止事件、有效时长与原始记录真实；
- 公共起点哈希一致，可写卷、上下文和产物独立；
- 不可读取 peer、Reference、隐藏 tests 和凭据；
- 最终 best 有实际方法快照，不只是高分数字。

## 实验与血缘

- B/R 使用冻结协议，全部适用 seed/replicate 都保留；
- 每个 result 的 run ID、源码、配置、receipt、artifact、checkpoint 和时间窗一致；
- 负结果与补充敏感性没有被删除或冒充正式结果；
- 独立重载和质量门通过。

## Docker 与 Harness

- 开发 Compose 静态配置、目标主机 GPU 可见性和真实最小运行分别验证；
- Harbor task 通过目标版本解析；
- Oracle 证明任务可解，Starter/负例防止平凡满分和 reward hack；
- tests 在所有路径写合法 reward；
- 真实 Agent Trial 和目标 GPU backend 状态明确。

## 平台登记与回读

平台登记是交付链的最后一跳，不由本地 READY 自动推出。执行远端写入前：

1. 从当前期权威登记源读取期次、题号、记录主键和可写字段；不得从旧表、目录名、文件名或历史报告推断。
2. 将任务标题、论文、产物哈希、QA 结论和记录主键逐项对齐。找不到精确记录、命中多条或已被他人领取时停止，不创建替代记录。
3. 先读取 schema 和当前值，再做精确记录更新。状态只使用 `accepted`、`rework_required`、`pending/incomplete` 三类语义；证据不足或尚未定论时保持 pending，不为填满表格强行标通过或返修。
4. 领取、提交和组长初筛分开处理。领取只证明任务归属；附件上传只证明材料存在；初筛状态必须绑定该任务自己的 QA 报告与产物，不能继承另一任务的结论。
5. 每次写入后立即回读同一记录并逐字段比较。API 返回成功、上传完成或界面出现文件名，都不能单独证明登记完成。
6. 权限失效、原组织账号不可用或权威源不可达时，停止远端写入并生成本地脱敏 handoff；不得复用旧凭据、猜字段 ID 或改写其他人的记录。

公开证据只保留去标识化 schema、状态机、产物哈希、验证时间和失败类型。不要提交真实表格链接、访问令牌、用户/记录 ID、内部题号映射、截图或表格正文。公共 CI 只验证 schema、幂等、状态转换和隐私规则，不连接真实协作平台。

任何适用硬门失败即 NOT READY。静态检查不能升级成动态运行，Compose GPU 成功不能升级成 Harbor GPU 成功。
