# 中文一页 Typst 简历

## Core rule

**一页 A4 是硬门。** 编译后 `pages != 1` 就没有完成。履历、论文状态和数字必须能指向用户提供的可信产物；没有证据就删除或标待确认，不从示例、旧简历或其他候选人材料继承。

先定位当前仓库的 `resume.typ`、字体目录、输出约定和构建脚本。所有命令使用仓库相对路径或由用户明确提供的项目根变量；不要把用户名、真实联系方式、个人站点、雇主、内部项目名或本机绝对路径写入 skill、日志或公开 fixture。

## 编译与渲染

先探测仓库已有命令和 `typst`。没有项目脚本时，可从仓库根运行：

```bash
typst compile --root . --font-path fonts path/to/resume.typ /tmp/resume-preview.pdf
```

输出文件默认写到临时目录。只有用户明确要求且仓库约定允许时，才写入项目目录。验收 PDF，不用缓存缩略图代替真实渲染。

## 字体

- 中文正文选择项目实际提供或系统可用的宋体类字体；拉丁文字选择清晰的衬线或无衬线字体。
- 标题和 `#strong` 使用真正支持目标字重的黑体类字体；不要用不支持粗体的字体伪造加粗。
- 编译前探测字体，不假设某台机器上的专有字体在另一台机器可用。

## 版面调整顺序

统一维护 `line-leading < item-gap < project-gap < section-gap` 四档间距 token。页面过空或溢出时，按以下顺序调整：

1. 删除没有证据、重复或低价值的内容。
2. 修复孤行、短尾行和不可断开的块。
3. 小幅同步调整间距 token 和页边距。
4. 最后才调整字号；不得以不可读的字号换取一页。

用渲染图的实际墨水边界判断视觉平衡，而不是只看源码中的 margin 数值。年份、奖项或项目块若整体跳到第二页，应先检查 block 是否可断，再收缩正文。

## 避免难看的短尾行

换行后只剩两三个字、标点落在行首或分隔符独占行都算缺陷。

- 用项目已有的不可断行 helper 将短语及其标点捆绑。
- 补充内容优先填已有末行，不要为“写满”制造新的空泛条目。
- 不通过插入不可见字符、缩放文本或负间距掩盖溢出。

## 论文与研究经历

- 状态严格使用证据中的当前状态，例如 `Under Review`、`Accepted` 或 `Published`；不得把在审写成已接收。
- 写清本人角色、比较对象、方法变化和可答辩结果；不要用模块清单冒充贡献。
- 数字只从当前项目的主表、结果账本或用户明确提供的材料读取，并保留来源位置。
- 用户要求删减时保留创新和对照故事；要求补数字时优先补入已有条目，不凭空增加实验。

## 验收

声称完成前至少验证：

1. Typst 编译退出码为 0，且没有缺字或字体 fallback 警告。
2. PDF 页数恰好为 1。
3. 渲染为 PNG 后人工检查四边墨水边界、孤行、短尾行、分隔符、重叠和裁切。
4. 简历中的日期、状态、数量和联系方式逐项回指到本次用户材料；未核实项显式报告。
5. `git diff` 只包含本次请求范围，预览 PDF 和临时图片未被提交。

可用当前环境已有的 PDF 库读取页数和渲染；依赖不存在时先报告，不为一次检查静默改写项目依赖。

## Hard stops

- 不把任何示例中的姓名、联系方式、公司、路径、项目数字或论文状态复制到用户简历。
- 不把预览 PDF、图片、字体许可证不明的字体或私人证据文件提交到公开仓库。
- 不用单一“编译成功”替代一页、可读性和事实核验。
- 不顺手格式化或改写无关 Typst 文件。
